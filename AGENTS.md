# AGENTS.md

Concise orientation for AI agents working in this codebase.

## Project Overview

Personal blog and portfolio for Jairo R. Mejia Aponte, an Embedded Software Engineer, branded as
"Oops I bug it again · J. Mejia". Built with Docusaurus 3.10.1 (React 18, JavaScript — no TypeScript),
hosted on Firebase. Dark mode default, blue/dark-blue palette, JetBrains Mono headings, Source Sans 3
body. Content focuses on Yocto, embedded Linux, and embedded systems.

## Architecture

**Rendering:** `docusaurus.config.js` wires `preset-classic` (blog + docs + pages + theme). Custom CSS
loads in cascade order: `variables.css` → `fonts.css` → `custom.css`, so tokens are defined before use.

**CSS layer order:**

1. `variables.css` — design tokens, overrides Infima `--ifm-*` variables
2. `fonts.css` — Google Fonts `@import`
3. `custom.css` — component-level overrides, navbar responsive trick, footer styles

**Swizzled components** (wrap originals, do not fork them):

- `src/theme/BlogPostItem/` — appends `<BlogComments />` (from `src/components/Comments/`); the
  wrapper renders the thread only when `frontMatter.enableComments === true` and this is the full
  post page
- `src/theme/BlogPostItem/Content/` — renders `<BlogCover />` (from `src/components/Cover/`) before
  `<MDXContent>`, so the cover lands below the title/metadata and above the post body. Docs opt in
  manually by importing `<DocCover />` from the same family.
- `src/theme/BlogPostPage/` — passes an explicit `isBlogPostPage` marker to `BlogLayout` so every post
  (even those without a TOC) gets the wide doc-style layout
- `src/theme/BlogLayout/` — applies the wide layout to blog post pages
- `src/theme/Footer/` — custom site footer
- `src/theme/DocItem/Layout/` — appends `<DocComments />` (from `src/components/Comments/`); the
  wrapper renders the thread only when the doc sets `enableComments: true`. Comments are opt-in
  per item, symmetric with the blog (see `adr/0002`)

## Content Authoring

**Blog post:** date-only folders, which may hold more than one post:

```
blog/YYYY-MM-DD/
└── my-post-name.md
```

```yaml
---
title: My Post Title
authors: [jrmejiaa]
tags: [yocto, linux]
enableComments: true   # omit to disable comments
---
```

> Note: the `blog-cover-prompt` skill documents a folder-per-post convention
> (`blog/YYYY-MM-DD-slug/index.md` with a clean `cover.png`). The repo has NOT
> migrated to that layout — it still uses date-only folders with per-post cover
> names (e.g. `cover-hidden-gems.png`) to avoid collisions when a date holds
> multiple posts. This mismatch is deliberate and tolerated; do not "fix" files
> to match the skill.

**Blog cover images:** covers render **automatically** from frontmatter via `<BlogCover />` (in the
swizzled `BlogPostItem/Content`). Do **not** add an `<img>` or `![]()` for the cover in the post body —
that would double-render it. The cover block (image + a collapsible "Generated with …" AI-attribution
footer) renders on the full post page only, and **only when all four** fields are present; missing any
one renders nothing:

```yaml
image: ./cover.png
imageStyle: isometric              # gate + skill anti-monotony signal (not displayed)
imageModel: Gemini Nano Banana Pro
imagePrompt: "<the full generation prompt>"
```

- The component uses the webpack-resolved `assets.image` from `useBlogPost()`, **not**
  `frontMatter.image` (which stays the raw `./…` string and 404s if used as a raw `<img src>`).
- These fields are produced by the **`blog-cover-prompt`** skill's finalize mode; the author saves the
  image file at the path themselves.

**Doc page (yocto or linux):** drop a `.md` file into `docs/yocto/` or `docs/linux/` — autogenerated
sidebar picks it up automatically.

**Doc page (coding):** create the file under `docs/coding/`, then add its path to the relevant category
in `sidebars.js`.

## Repo-Specific Patterns

- **JavaScript with JSDoc** — all source files are `.js`. Do NOT create `.ts` or `.tsx` files.
  `@docusaurus/types` is installed only to power JSDoc `@type` annotations.

- **Navbar title trick** — the `title` in `docusaurus.config.js` is the full string for SEO/`<title>`.
  `custom.css` hides it with `font-size: 0` on `.navbar__title` and uses a `::after` pseudo-element
  to inject "Oops I bug it again · J. Mejia" on desktop and "J. Mejia" on mobile (`max-width: 768px`).

- **Comments** — opt-in per item, symmetric across contexts: a post or doc shows a Giscus thread
  only when its frontmatter sets `enableComments: true` (see `adr/0002`). Section `welcome-*` hub
  pages omit it. The gate lives in the `BlogComments` / `DocComments` wrappers; the shared
  `CommentsThread` core reads `useColorMode()` and passes `colorMode` directly as the Giscus
  `theme` prop (`'dark'` or `'light'`).

- **`HomepageFeatures` is unused** — `src/components/HomepageFeatures/` is a legacy scaffold artifact.
  Do not import it.

- **Firebase hosting** — deploy with `npm run build` then `firebase deploy --only hosting`.
  Project ID: `oops-i-bug-it-again`. This is not GitHub Pages.

## Design Tokens

All tokens live in `src/css/variables.css` — treat that file as the source of truth (do not rely on a
copied list here; the previous hardcoded table drifted out of sync). Token groups:

- **Primary blue scale** — Infima `--ifm-color-primary`, `-dark/-darker/-darkest`, `-light/-lighter/-lightest`
  (base `#3b82f6`). Used for interactive/accent color.
- **Blue-tinted gray scale** — `--ifm-color-gray-0` … `--ifm-color-gray-1000`, the neutral surfaces and
  content colors; dark mode overrides several under `:root[data-theme="dark"]`.
- **Custom `--site-*` tokens** — `--site-color-accent` (`#06b6d4`, cyan accent) and the TerminalHero set
  `--site-terminal-bg`, `--site-terminal-border`, `--site-terminal-green`, `--site-terminal-blue`,
  `--site-terminal-cyan`, `--site-terminal-dim`.

**Typography:** `--ifm-font-family-base` (Source Sans 3), `--ifm-font-family-monospace` and
`--ifm-heading-font-family` (JetBrains Mono). `--ifm-font-size-base` is `100%`, bumped to `112%` on
desktop (`min-width: 997px`) — so `rem` units scale up slightly on wide screens.
